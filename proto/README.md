# Nakode API schema

`nakode/v1/nakode.proto` is the public, language-neutral frontend contract.
The native Rust server implements it and every frontend consumes a generated
client plus the small high-level SDK layer for its language.

The schema must expose every operation and every canonical state projection
needed by a feature-complete frontend. The TUI has no private product API.
Adding behavior directly to a client because the schema lacks an edge violates
the Nakode architecture; add the server operation and schema definition first.

Generate Go and TypeScript stubs under `gen/` with
`buf generate proto --template proto/buf.gen.yaml`. Those multi-target
artifacts are build outputs and are not committed. Rust stubs are generated by
the `nakode-api` crate using a vendored `protoc`, so building Nakode does not
require a system Protobuf installation.

Generated transport stubs are deliberately not the whole SDK. Language SDKs
must also own connection recovery, idempotency keys, subscription resumption,
snapshot replacement, paging, and artifact hydration. A frontend owns only
device-local presentation state and rendering.
